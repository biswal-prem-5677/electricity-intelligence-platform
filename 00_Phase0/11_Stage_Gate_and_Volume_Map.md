# Stage Gate and Documentation Volume Map

## How the suite maps to the original planned volumes

| Planned volume | Current controlled documents | Deliverable required before build |
|---|---|---|
| 1. Product Definition | Phase 0 overview through portfolio, opportunity and cost documents | Approved PDD, target SKU and decision log |
| 2. Hardware Engineering | Hardware SRS, Hardware Engineering, PCB Design | Schematics, released BOM, calculations, layout package, hazard analysis |
| 3. Firmware SRS | Firmware SRS and Firmware Engineering | Interface-control document, task timing, threat model, release plan |
| 4. Cloud & Backend | Backend SRS and Cloud Engineering | Data schema, API/MQTT contracts, SLO/DR runbooks |
| 5. AI System | AI Roadmap, AI SRS and AI Engineering | Model/rule cards, evaluation data and rollout gate |
| 6. Mobile App | Mobile SRS and Mobile Experience | User-flow/wireframe review and accessibility test evidence |
| 7. Manufacturing & Cost | Cost Analysis, Manufacturing SRS, Commercialization | RFQs, production test specification, quality plan, unit economics |
| 8. Testing & Validation | Testing SRS and Testing/Certification Plan | Traceability matrix, DVP&R, laboratory plan and pilot protocol |
| 9. Deployment Roadmap | Deployment SRS and Operations SRS | Runbooks, support model, staged release plan |
| 10. Future Research | AI Roadmap and Future Opportunity Backlog | Separate research charters, not MVP promise |

## Document-control rule

The repository is **Architecture Baseline 0.2**, not a claim that all design files are complete. As decisions mature, attach controlled artefacts—schematics, PCB sources, BOM, FMEA, DVP&R, API schemas, test reports and supplier RFQs—under their volume. A 500–800-page enterprise package must be earned through these artefacts and review evidence, not generated as unverifiable prose.
